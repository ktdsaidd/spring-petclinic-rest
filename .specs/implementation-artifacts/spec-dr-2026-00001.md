## Intent

**Problem:** 현재 방문(Visit) 예약에는 반려동물, 방문 날짜, 설명만 기록되고 어느 수의사가 진료하는지가 시스템에 기록되지 않아, 접수 데스크가 수기 장부로 관리하고 보호자의 문의에 대응하기 어렵다.

**Approach:** `visits` 테이블에 `veterinarian_id` 컬럼을 추가하고, Visit DTO/REST API에 수의사 정보를 포함·수정·조회하도록 전체 레이어(DB, Entity, Mapper, Repository, Controller, OpenAPI 스키마, 테스트)를 변경한다.

## Boundaries & Constraints

**Always:**
- 프로젝트의 기존 아키텍처 유지 — 3중 리포지토리 구현(JDBC, JPA, Spring Data JPA)을 모두 동시 수정
- MapStruct 자동 생성 코드(`target/generated-sources`) 직접 수정 금지 — `openapi.yml` 수정 후 `mvn clean install`로 재생성
- 기존 프로필(`h2`, `hsqldb`, `mysql`, `postgres`) 스키마를 모두 변경
- `spring-data-jpa` 프로필이 기본 프로필 — 해당 구현체가 우선 적용됨
- 모든 변경은 `veterinarian_id` 컬럼의 NULL 허용으로 기존 데이터 영향 없음

**Ask First:**
- `VisitDto` 응답에 `Vet` 객체를 중첩 포함하는 방식 (Pet→PetType 패턴 참조) — 이미 사용자 확정

**Never:**
- 프론트엔드(UI) 변경 — 이 프로젝트는 백엔드 REST API 전용
- 기존 방문 데이터의 수의사 정보 소급 입력
- 수의사별 예약 현황 조회 기능 (별도 SR 후보)

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|

**Acceptance Criteria:**
- Given `visits` 테이블에 `veterinarian_id` 컬럼이 추가됨, when 데이터베이스 프로필 전환 시, then 모든 프로필(H2, MySQL, PostgreSQL, HSQLDB)에서 스키마 변경이 적용된다
- Given `VisitDto`에 `veterinarianId`가 포함됨, when `POST /api/visits`를 호출하면, then 수의사 ID가 방문 기록에 저장되고 `VisitDto` 응답에 `veterinarian` 중첩 객체로 반환된다
- Given 방문 수정 시 `VisitFieldsDto`에 `veterinarianId`가 NULL로 전달됨, when `PUT /api/visits/{visitId}`를 호출하면, then 수의사 정보가 NULL로 변경된다
- Given 기존 방문(수의사 미지정)이 존재할 때, when `GET /api/visits`를 호출하면, then 기존 방문은 `veterinarian: null`로 반환되고 신규 방문은 수의사 정보 포함
- Given `veterinarianId`에 유효하지 않은 수의사 ID를 전달하면, when 방문 등록을 시도하면, then 404 Not Found 오류가 반환된다

## Design Notes

### VisitDto 응답 형식 — Vet 객체 중첩
기존 `Pet`이 `type: PetType`을 중첩 포함하는 패턴을 참조하여, `VisitDto` 응답에 `veterinarian: Vet` 객체를 중첩 포함한다.

예시 (JSON):
```json
{
  "id": 1,
  "date": "2026-10-04",
  "description": "건강 검진",
  "petId": 8,
  "veterinarian": {
    "id": 3,
    "firstName": "James",
    "lastName": "Carter",
    "specialties": []
  }
}
```

기존 방문(수의사 미지정)의 경우:
```json
{
  "id": 2,
  "date": "2026-01-15",
  "description": "접수 완료",
  "petId": 5,
  "veterinarian": null
}
```

### 3중 리포지토리 동시 변경
프로젝트는 3가지 데이터 접근 방식을 프로필로 분리한다. 하나만 변경하면 프로필 전환 시 버그가 발생하므로 다음 3개를 반드시 모두 변경한다:
1. `JdbcVisitRepositoryImpl` — JDBC 템플릿 쿼리에 `veterinarian_id` 추가
2. `JpaVisitRepositoryImpl` — JPA는 `Visit` 엔티티의 `@ManyToOne` 매핑을 자동 처리하므로 별도 쿼리 변경 불필요
3. `SpringDataVisitRepository` — Spring Data JPA가 엔티티 기반 쿼리 생성을 자동 처리하므로 별도 변경 불필요

### REQ-001 vs REQ-003 필수 여부 차이
- **REQ-001 (방문 등록)**: `veterinarianId` **필수** — 누락 시 400 Bad Request
- **REQ-003 (방문 수정)**: `veterinarianId` **NULL 허용** — 기존 방문에서 수의사를 "미지정"으로 변경 가능
